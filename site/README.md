# skeletonkey.run

Public website for SkeletonKey, served by Cloudflare Pages (project name: `skeletonkey`). This directory is the site source; run all commands from `site/`.

## Local

```bash
cd site
npm install
npm run dev          # wrangler pages dev, http://127.0.0.1:8788
npm run check        # tsc --noEmit (waitlist Pages Function)
npm run build:sitemap  # regenerate public/sitemap.xml from public/**/index.html
```

`public/sitemap.xml` lists the public HTML pages (currently 178 URLs). `public/robots.txt` has `Sitemap: https://skeletonkey.run/sitemap.xml`. After deploy, resubmit that sitemap in Google Search Console (domain property on beizhangbill@gmail.com).

## Deploy

From `site/`, after `npx wrangler login` if needed:

```bash
npm run deploy       # = wrangler pages deploy  (Pages project: skeletonkey, host: skeletonkey.run)
```

Then confirm `https://skeletonkey.run/sitemap.xml` returns 200, and that `https://skeletonkey.run/robots.txt` includes the Sitemap line (Cloudflare may prepend managed Content Signals). Do not run deploy unless Bei is triggering it.

The waitlist form posts to a Pages Function (`functions/api/waitlist.ts`) that stores emails in the `WAITLIST` KV namespace already bound in `wrangler.toml`. List signups: `npx wrangler kv key list --binding WAITLIST --prefix email: --remote`.

Design notes are in `DESIGN.md`. API Directory HTML under `public/apis/`, `public/apis.json`, `public/llms.txt`
and `public/sitemap.xml` are generated by `scripts/build_apis.py` from the repo's own data: the `data/apis/*.yaml`
shards (two levels up, canonical for every field they carry) merged with the committed `data/vendor-research.json`
overlay and `data/routes/` (research-only fields and aggregator/route data the shards don't carry -- see
`data/README.md`). Nothing outside the repo is read, so a clean clone can build the site:

```bash
python3 scripts/build_apis.py              # writes into public/ in place
python3 scripts/build_apis.py --out DIR     # writes into DIR instead (e.g. for a test build)
```

Don't run that against `public/` unless you intend to regenerate those pages. To refresh `data/vendor-research.json`
and `data/routes/` from a new research pass over the external index, run
`python3 scripts/export_site_data.py --index /path/to/index.yaml` (the only script here that reads outside the repo).
