`vendor-research.json` and `routes/` are a snapshot of our own research conclusions as
already published on skeletonkey.run (source: the SkeletonKey research index, exported with
`scripts/export_site_data.py` on 2026-11-24). `data/apis/*.yaml` (two levels up) are the canonical,
version-controlled shards and win on any overlap -- see `build_apis.py`'s merge rule. New fields should go
into the shards first, not into this snapshot; this directory only carries research-only fields the shards
don't carry yet.

`collection.json` is a small, hand-maintained overlay for the catalog-scope decision (which vendors/
aggregators are listed vs. hidden) -- not regenerated by `export_site_data.py`.
