smol machines

Checked 2026-10-25

PAYG

Hosted REST API for creating and controlling hardware-isolated Linux microVMs ("machines") that run code, agents or untrusted workloads; the same machine model also runs locally or self-hosted via the open-source smolvm engine.

API surface

Official docs
https://smolmachines.com/docs/cloud/api-reference
EndpointDoesReturnsDocs
POST /v1/machinesCreate a persistent cloud microVM from an OCI image or .smolmachine registry reference, specifying CPU, memory, network policy, env, ports and lifecycle limits.The created machine record including its id; the examples read '.id' from the JSON response.Docs
POST /v1/machines/{id}/execRun a command in a machine; command may be a shell string or an argv array, with optional cwd, env, stdin, timeoutSeconds, stream and background.Output per stream as UTF-8 text (stdout/stderr, capped at 1 MiB) and as base64 (stdoutB64/stderrB64); use ?output=text or ?output=b64 to get one family.Docs
POST /v1/machines/{id}/jobsRun a command detached as a job; takes command with optional cwd, env, user and timeoutSeconds, wakes a stopped machine and keeps it from auto-stopping.202 immediately; the job's stdout, stderr and exit code are kept in the machine for later reads.Docs
GET /v1/machines/{id}/files/{path}Download a file from the machine filesystem at the given absolute guest path without its leading slash; needs the machine:files scope.The file contents as the response body.Docs
PUT /v1/registry/credentialsStore a pull credential for an external registry host (such as ghcr.io or Docker Hub) so cloud machines can pull private images.Credential record; the password is never returned and the list shows only the username.Docs
